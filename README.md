# Практика №5. SOLID и архитектура

> ⚠️ **Только пройденные на паре концепции.** В коде можно применять лишь те возможности
> языка и ООП, которые разбирались на занятиях. Если в работе используется то, чего на паре
> не было, это считается признаком генерации кода ИИ-ассистентом — и работа **не засчитывается**.

## Как получить эту лабу

Эта лаба лежит в шаблоне `java101-lab5-template`. Шаблон редактировать нельзя — сделай **свою копию**:

1. Открой страницу шаблона: **https://github.com/java101-ranepa-26-27/java101-lab5-template**
2. Нажми зелёную кнопку **Use this template** → **Create a new repository**.
3. **Owner** — выбери организацию **java101-ranepa-26-27**.
4. **Repository name** — имя должно соответствовать маске: `java101-lab5-lastName`
   (`lastName` — фамилия латиницей). Имя должно быть уникальным в организации.
5. **Visibility** — оставь **Private**.
6. Нажми **Create repository**.

Клонируй его в IDE: на странице своего репозитория — зелёная кнопка **Code** → **HTTPS** → скопируй
ссылку, затем в IDE **File → New → Project from Version Control…** → вставь ссылку → **Clone**.

## Как завести ветку

В OpenCode нажми на текущую ветку в правом нижнем углу окна — там написано `main`.
Выбери **New Branch…**, введи `task-5` и нажми **Create**.

Проверка: в правом нижнем углу написано `task-5`, а не `main`. Всю работу делай в этой ветке.

В своём пакете:

1. Починить решение так, чтобы оно соответствовало принципам SOLID. Поведение должно остаться
   рабочим: программа запускается и делает то же самое.
2. В каждом классе, который подвергся рефакторингу, добавить короткий Javadoc: что вы поменяли
   и какой принцип этим закрыли.
3. Разложить классы по пакетам по слоям: `domain`, `application`, `infrastructure` и т.п.
   Точка входа `Main` остаётся.

В исходном виде проект компилируется и запускается, но SOLID нарушает. Запустите `Main` своего
пакета и посмотрите, что происходит.

## Сдача работы

После выполнения работы выполняется коммит + пуш + Pull Request в `main`.

### Как открыть Pull Request

1. Открой страницу своего репозитория на GitHub и обнови её. Сверху появится жёлтая плашка
   **Compare & pull request** — нажми её.
2. Проверь направление слияния: **base: `main`**, **compare: `task-5`**.
3. В поле **Title** напиши, например, `Практика 5: SOLID и архитектура`.
4. В описании PR добавь **скриншот выполнения класса `Main`**.
5. Нажми **Create pull request**.
